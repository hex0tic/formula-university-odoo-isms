## Засах дараалал

1. **P1 — Эрхийн зөвшөөрлийн сервер талын хамгаалалт.** `university_access_governance/models/access_request.py:128` болон `recert.py:239` дэх бичилтийн хамгаалалт хэрэглэгчийн хүсэлтээр дамжиж болох context утгад итгэж байна. Хүсэлт гаргагч өөрийн мөрөнд write ACL-тай. Түр эрхийн автомат ажил `approved` төлөвтэй мөрүүдийг системийн эрхээр боловсруулдаг (`access_request.py:270`). Иймээс батлах урсгал тойрогдох эрсдэл нь релизийн саад. Дотоод зөвшөөрлийг клиентээс дамжуулах боломжгүй сервер талын механизмаар сольж, хамгаалсан талбарууд болон батлагчийн үүргийг шалгах тест нэмэх. Энэ нь кодын хяналтын дүгнэлт; ажиллагаатай орчинд эрх өөрчилж туршаагүй.
2. **P1 — Бодитоор хэрэгжиж буй хамгаалалт.** Staging-д MFA хэрэгжих огноо байхгүй. Одоогийн код өндөр нөлөөтэй зарим үйлдэл дээр TOTP идэвхжүүлсэн эсэхийг шалгадаг; тухайн үйлдэл бүрд дахин OTP оруулах эсвэл нэвтрэх хэмжээнд бүх давуу эрхтэнд мөрдүүлэх шийдэл гэж үзэхгүй. Аудитын гинжийн 888 мөр, PostgreSQL-ийн 2 trigger баталгаажсан ч гаднах бүртгэл хүлээн авагч, өөр эзэмшилтэй хадгалалт, гаднах нөөцийн сэргээлт батлагдаагүй. Автомат хяналт MFA ба инцидентийн SLA/хариуцагч дээр хоёр олдвор гаргасан.
3. **P2 — Давтаж болох release шалгалт.** `docs/roadmap/RUNBOOK.md:108`-ын суулгах команд Copilot-ыг орхисон. `odoo/scripts/run-tests.sh:12`-ийн анхдагч жагсаалт хуучин зургаан addon-оор хязгаарлагдана. Бүрэн суулгах болон бүрэн шалгах нэг эх жагсаалт гаргаж, ажлын урсгалын зэрэгцээ шалгалт, хөтчийн JS тест, цэвэр суулгалтаас эхэлсэн smoke шалгалтыг тусгана.
4. **P2 — Хэрэглэгчид харагдах дутагдал ба холболт.** Sidebar, breadcrumb, dark theme/контраст болон шүүлтүүр, экспортын дутууг засна. SSO, Moodle, SIEM, SMTP болон API-г тухайн үйлчилгээний зөвшөөрсөн туршилтын тохиргоогоор төгсгөл хүртэл шалгана. Элсэлт, төлбөр, тэтгэлгийг шаардлага тохирсны дараа тусад нь төлөвлөнө.

## Шууд хийсэн шалгалт

- Staging HTTP login 200. Үндсэн `orgil_isms`-д шинэ `formula_*` addon суугаагүй; staging `orgil_isms_stage`-д Command Center, ажлын консолууд, портал, Copilot болон шинэ GRC addon суусан.
- Staging-д унших горимоор: Доржсэмбэ болон Тэлмүүнд 15 эрсдэл, heatmap харагдсан; мэдээлэгч оюутанд хоёулаа хаалттай.
- Аудитын гинжийн 888 мөрийг хэшээр бүрэн шалгасан. Хяналтын найман сүүлийн үр дүнгээс зургаа PASS, хоёр FAIL; хоёул олдвортой. Энэ нь хяналтын систем ажилласны нотолгоо бөгөөд хоёр хяналт хангагдсан гэсэн үг биш.
- Staging зураг, QA тайланг шалгасан. Өргөн, жижиг дэлгэц болон өөр өөр эрхийн нотолгоо байгаа. Хөтчөөр бүх боломжийг дахин гүйлгээгүй.
- Шинэчлэлийн код, staging/үндсэн өгөгдөл, Git салбарыг өөрчлөөгүй. Туршилтад зөвхөн тухайн ажилд зориулж үүсгэсэн түр өгөгдлийн сан ашигласан.
- Prompt дахь 72 ID бүгд матрицад таарсан. Агентын хоёр Odoo логт 375 тест, 0 алдаа, 0 бүтэлгүйтэл бүртгэгдсэн. Аль алинд нь 22 addon-оос тест ажилласан нь логт харагдсан. Тусдаа test addon суулгасан эсэх ба тест агуулсан addon-ы тоог 375 гэсэн тоотой адилтгахгүй.
- Ижил commit болон Odoo image ашигласан хөндлөнгийн бүтэн гүйлт Python процессын `SIGSEGV` (`exit 139`)-ээр дууссан. Kernel болон coredump-ын мөрөөр процессын осол гэдэг нь батлагдсан; яг шалтгаан тодорхойгүй. Тестийн assert унасан гэж дүгнээгүй.
