# Formula University веб ба портал

Энэ өөрчлөлтийг `formula-erp` салбарын staging орчинд суулгасан. Өгөгдлийн сан `orgil_isms_stage`, Odoo `isms-stage-odoo`, хост `127.0.0.1:8070`. LAN шинэчлэлийн заавар болон элсэлтийн урсгал: `CAMPUS_LAN_RELEASE.md`.

| Хэсэг | Зам |
|--|--|
| Сургуулийн нийтийн веб | `/university` |
| Хөтөлбөрийн каталог | `/university/programs` |
| Элсэлтийн мэдээлэл, лавлагаа | `/university/admissions` |
| Оюутны портал | `/my/campus` |
| Багшийн портал | `/campus/teacher` (багшийн веб) |
| Зөрчил мэдээлэх | `/my/campus/incidents` (оюутан, багш) |

Сургуулийн сайтад нэвтрэх шаардлагагүй. Каталог зөвхөн нийтэлсэн хөтөлбөрийг харуулна. Элсэлтийн лавлагаанаас гадна өргөдөл илгээж, төлөвийн кодоор шийдвэрийг шалгана. Сургалтын алба баталсан өргөдлөөс оюутны бүртгэл үүсгэнэ. Системийн админ **Кампусын веб → Хөтөлбөр / Элсэлтийн лавлагаа** хэсгээс хөтөлбөр нийтэлж, лавлагааны төлвийг шийднэ. Оюутны болон багшийн академик бүртгэлд одоо байгаа Odoo бүлэг, ACL, Record Rule, серверийн урсгалыг хэвээр хэрэглэнэ.

Оюутны туршилтын нэвтрэх нэр `student@formula-campus.example`, багшийнх `teacher@formula-campus.example`. Улаанбаатарын цагийн бүсээр бэлтгэсэн сургалтын жишээ өгөгдөл: 3 хөтөлбөр, 9 багш, 72 оюутан, 15 хичээл, 360 бүртгэл, долоо хоногийн хуваарь, ирц, дүнгийн түүх. Порталд эдгээрийн хоёр нэвтрэх эрх идэвхтэй. Нэр, код дээр зохиомол өгөгдлийн давтагдсан тэмдэглэгээ байхгүй; гарал үүслийг XML ID болон сургалтын орчноор ялгана. Нууц үгийг репод хадгалахгүй.

Staging дээр вебийг анх суулгах, дараагийн дизайны шинэчлэл хийх команд:

```bash
docker exec isms-stage-odoo odoo -c /etc/odoo/odoo.conf -d orgil_isms_stage \
  --no-http --stop-after-init -i formula_campus_web \
  -u campus_university,campus_portal,campus_isms_bridge,formula_campus_web,formula_integration_hub,university_isms_helpdesk,formula_design_system,university_access_governance
docker restart isms-stage-odoo
```

`odoo/scripts/seed_formula_campus.py` нь зөвхөн `orgil_isms_stage`-д ажиллана. Анхны утга нь харах горим бөгөөд өөрчлөлтүүдийг буцаана. Хадгалахын тулд `FORMULA_CAMPUS_APPLY=1`; анх хэрэглэгч үүсгэхдээ хоёр тусдаа нууц үгийг орчны хувьсагчаар өгнө. Давтан гүйлт өмнөх нууц үг болон хичээлийн бүртгэлийг сольдоггүй.

Нийтийн вебийн хайлт, хөтөлбөрийн дэлгэрэнгүй, холбоос, лавлагаа хадгалалт; оюутны нэвтрэлт, хуваарь, дүн, ирц, PDF; багшийн нэвтрэлт, 24 оюутны жагсаалт, ирц ба дүнгийн хүсэлтийн UI-г Chromium-оор шалгасан. Портал, дизайны систем, эрхийн засаглал болон MFA-ийн тусгаарласан гүйлтэд 63 тест тэнцсэн. Эрхийн батлах урсгал үйлчлүүлэгчийн context-д найдахаа больсон; төлөвийг зөвхөн серверийн зөвшөөрсөн ажиллагаа солино.

Гар утасны апп, бодит Moodle/SSO холболт тусдаа дараагийн ажил.

### Портал, ажилтны чат ба ISMS-ийн эрх

| Бүртгэл | Академик ажил | Ажилтны #general | ISMS |
|--|--|--|--|
| Оюутан | Portal хэрэглэгч; өөрийн сургалтын мэдээлэл, хичээл сонголт | Хандахгүй | Порталаас зөрчил мэдээлнэ |
| Багш | Багшийн веб; хариуцсан хичээл, ирц, оюутны жагсаалт, дүнгийн хүсэлт | Ажилтны хэлэлцүүлгийн бүлгийг тусад нь олгосон үед | Порталаас зөрчил мэдээлнэ; ISMS-ийн дотоод эрхийг үүргээр тусад нь олгоно |
| Сургалтын алба | Сургалтын бүртгэл, шийдвэрийн урсгал | Ажилтны хэлэлцүүлгийн бүлгээр | ISMS-ийн дотоод эрхийг үүргээр тусад нь олгоно |
| ISMS-ийн баг | Академик эрхийг үүргээр тусад нь олгоно | Ажилтны хэлэлцүүлгийн бүлгээр | Тухайн үүргийн дагуу ирсэн зөрчлийг хүлээн авч шийдвэрлэнэ |

Зөрчил мэдээлэхэд ISMS-д бүртгэлийн дугаар үүснэ. Мэдээлэгч өөрийн илгээсэн мэдээллийн гарчиг, дугаар, төлвийг л порталаас харна. Илгээсэн тайлбар, дотоод тэмдэглэл болон хариуцагчийн мэдээлэл шинжээчийн эрхээр нээгдэнэ.

Системийн админ #general-д нэвтрэх шаардлагатай ажилтанд **Ажилтны хэлэлцүүлэг (#general)** бүлгийг олгоно. Шинэчлэлийн үед өмнө нь #general-д байсан дотоод ажилтнуудын хандалтыг хадгалж, оюутан болон багшийн хандалтыг тусгаарлана. Багшид суваг нээх шаардлагатай бол админ уг бүлгийг нэмж өгнө. Оюутанд ажилтны нэмэлт үүрэг шаардлагатай бол тусдаа ажилтны бүртгэл ашиглана. Шинэчлэл хуучин оюутны бүртгэлээс ажилтны болон нэмэлт аппын бүлгийг салгана; сургалтын бүртгэл, нэвтрэх нэр, нууц үг хэвээр байна. Оюутан ба удирдлагын академик үүргийг нэг бүртгэлд давхар олгосон бол шилжилтийн өмнө бүртгэлийг тусгаарлах шаардлагатай.

Staging шинэчлэхдээ `campus_university,campus_portal,campus_isms_bridge,formula_campus_web,formula_integration_hub,university_isms_helpdesk` модулийг хамт шинэчилнэ. Хуучин өгөгдлийн санд ахлах ISMS үүргээр дамжаагүй, академик бүлгээс өвлөсөн Reporter эрхийг цэвэрлэнэ. Тусад нь гар аргаар олгож байсан үндсэн Reporter эрхийг хуучин өвлөсөн мөрөөс ялгах боломжгүй тул шаардлагатай хэрэглэгчид дахин олгоно.
